# Configuration

Credentials come from the environment through `requireEnv`/`optionalEnv`
(`src/integrations/env.ts`): `.dev.vars` locally, `wrangler secret put` in production. Non-secrets
live in `wrangler.jsonc` → `vars` and can be overridden by the same name in `.dev.vars`. Nothing is
read at import time, so a missing value fails the route or tool that needs it with a clear
message while `/healthz` keeps answering.

## Variables

| Variable | Secret | Purpose |
|---|---|---|
| `ANTHROPIC_API_KEY` | yes | the model |
| `GITHUB_APP_ID` | no | the App's id |
| `GITHUB_APP_PRIVATE_KEY` | yes | the App's private key (PEM as downloaded); mints installation tokens |
| `GITHUB_WEBHOOK_SECRET` | yes | the App's webhook secret; verifies deliveries to `/channels/github/webhook`. The route answers 503 until it is set. |
| `GITHUB_ALLOWED_REPOS` | no | optional comma-separated `owner/repo` allowlist on top of where the App is installed. Unset means every repository the App is installed on. |
| `ELEVENLABS_API_KEY` | yes | text-to-speech |
| `ELEVENLABS_VOICE_ID` | no | the voice (default: ElevenLabs' stock "Brian", `nPczCjzI2devNBz1zQrb`) |
| `ELEVENLABS_MODEL_ID` | no | the model (default `eleven_multilingual_v2`; must support the timestamps endpoint) |
| `VIDEO_URL_SECRET` | yes | signs the video links (`openssl rand -hex 32`). Rotating it invalidates every link posted so far. |
| `PUBLIC_BASE_URL` | no | this Worker's public origin, used in the links (`http://localhost:5173` locally) |
| `OPERATOR_TOKEN` | yes | bearer token for the `/agents/*` mount; the mount answers 503 without it |
| `SANDBOX_TRANSPORT` | no | `rpc`: one connection per container instead of one subrequest per call. Keep it. |

## Bindings (`wrangler.jsonc`)

| Binding | Kind | Purpose |
|---|---|---|
| `Sandbox` | Durable Object + container (`./Dockerfile`) | the render environment, one instance per pull request |
| `EXPLAINER_VIDEOS` | R2 bucket (`explainer-videos`) | videos, posters and each run's `meta.json` |
| `FluePrExplainerAgent` | Durable Object (generated by Flue) | the agent's conversations and persistent state |

The `migrations` list must name every Durable Object class once. Append a tag for a new agent;
never edit or reorder a deployed entry (Cloudflare refuses the deploy).

## Cost knobs

- **Container instance type** (`containers[].instance_type`): render time scales with vCPUs;
  `standard-3` (2 vCPU, 8 GiB) renders a 60 s film in a few minutes. Smaller types risk Chromium
  running out of memory at 1080p. `max_instances` caps how many pull requests render at once.
- **Model** (`useModel` in the agent): `anthropic/claude-opus-5` with medium thinking for the
  build; a run is a long agentic session (dozens of tool calls). Compaction uses Haiku.
- **Narrations**: capped at 6 per pull request across all its runs; the model is told to narrate
  once, after the script is final. ElevenLabs bills per character.
- **Video length**: at most 60 seconds, and shorter for small changes (the bands in
  [how-it-works.md](how-it-works.md#length)). Shorter films render faster and narrate cheaper.
- **Who can trigger**: write access on the repository, by GitHub's `author_association`, plus the
  optional `GITHUB_ALLOWED_REPOS` allowlist. There is no per-repository daily cap; see
  [security.md](security.md#known-gaps).

## Changing the behavior

The agent is `src/agents/pr-explainer.ts`. Three places matter:

**The instructions** are the template string returned by `instructions()`. They describe the
stages, the structure of a pull-request explainer (purpose, mechanism on real hunks, the diff as a
stat card, where to start reviewing), and the visual rules the HyperFrames skill does not already
cover. Prefer moving a rule into code (a tool that renders output, a guard that throws) over
adding a sentence here; prompts bend, code does not.

**The limits** are constants next to the code that enforces them:

| Constant | Default | Effect |
|---|---|---|
| `MAX_VIDEO_SECONDS` | 60 | ceiling on the rendered file, enforced in `render_and_publish` |
| `END_HOLD_SECONDS` | 1.5 | silence after the last word; the narration must end before it |
| `BUDGET_WORDS_PER_SECOND` | 2.0 | turns a time budget into a word cap (leaves room for pauses) |
| `WORDS_PER_SECOND` | 2.4 | the voice's speaking pace, used to size cuts after an overrun |
| `lengthBand()` | four bands | target length and word cap by substantive lines changed |
| `MAX_NARRATIONS` | 6 | narrations per pull request, across runs |
| `MAX_VIDEO_BYTES` | 200 MB | sanity ceiling on the upload |
| `SKIP_PATTERNS` | lockfiles, `dist/`, `vendor/`, snapshots, minified and binary files | what counts as noise when sizing the change |

**The comments** are rendered by `renderStatus()` (progress) and `renderExplainerComment()`
(final). The final one is also what the channel rewrites when the pull request closes, so keep
both forms in that function.

The HyperFrames side (scene contract, spec reference, CLI) comes from the skills the container
image ships; `Dockerfile` pins the CLI version and copies its skills into
`/workspace/.agents/skills`. Bump `HYPERFRAMES_VERSION` to pick up newer skills, then re-read the
instructions against them.

## Adding tools

`useTool(defineTool({ name, description, input: v.object(...), run }))` inside the agent. The
description is the model's only documentation. Bind destinations and credentials in code; the
model chooses arguments, never the repository, the bucket or an API key. Tool outputs must be JSON
values (use `type`, not `interface`, for returned shapes). Tools that need the container take
`harness: true` and get `harness.sandbox`.

Anything that acts on the outside world should check its inputs against state the agent recorded
in code, the way `post_explainer_comment` refuses a video URL other than the one
`render_and_publish` produced in the same run.
